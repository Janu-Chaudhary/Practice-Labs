Quiz-day traps & method

The small things that cost whole questions, and a routine for any terminal task, even one you've never seen.

Method for any terminal task

The checker grades the final state: which branch you're on, where each branch points, how many commits there are, what is inside the files. It does not see your commands. So read the "What was checked" list first. That list is the real task.

A 6-step routine

  1. Read "What was checked" first. Turn each line into a goal, e.g. "main has 4 commits" or "branch X points at commit Y".
  2. Look before you act: pwd, ls, git status, git branch, git log --oneline --graph --all, docker ps -a.
  3. Predict the final state in one line, e.g. "after the merge, main = base + mine + theirs + merge commit = 4".
  4. One command at a time. Read each command's output before typing the next. Errors are usually explained in that output.
  5. Verify against the checks with the same look-commands as step 2. Count commits with git log --oneline | wc -l.
  6. Respect the "Stop" line. Don't push, delete or add commits that it forbids. An extra commit fails a commit-count check.

The traps (each one has cost real marks)

TrapWhat to do instead
docker build -t app:1.0Missing the build context. Always end with a folder: docker build -t app:1.0 .
docker run app:1.0 -p 8080:3000Anything after the image name becomes the container's command. Options go before the image: docker run -d -p 8080:3000 app:1.0
-p 3000:8080 backwardsIt's HOST:CONTAINER. The app's own port goes on the right.
git merge x then stuck in vimEsc :wq Enter. Better: git merge x --no-edit, or after resolving a conflict git commit --no-edit.
Resolved a conflict but commit failsYou must git add file after editing it. That's how git learns the conflict is resolved.
Conflict markers left inDelete every <<<<<<<, ======= and >>>>>>> line. Check with grep -n "<<<<" file.
Committed on the wrong branchCheck git branch before committing. Use git switch -c name to create a branch and move onto it.
git commit -am with a new file-a only includes files git already tracks. New files need git add first.
One extra commitgit reset --soft HEAD~1 undoes the last commit but keeps its changes staged.
> reports/x.txt: No such file or directoryThe folder must exist first: mkdir -p reports
Second > wiped the first result> replaces the file, >> adds to the end. Use > for the first write, then >>.
grep A f1 | grep B f2The second grep reads f2 and ignores the pipe. Give the file only to the first grep: grep A f1 | grep B
grep with 2 files adds file: prefixesUse grep -h, or grep one file at a time in the order the task asks.
mv before reading the fileDo the reading/grepping first, then move. Or use the file's new path.
Renamed a file with plain mv in a repoUse git mv old new, or mv then git add -A, so git records the rename.
Edited an already-applied migrationFlyway's checksum check fails. Never edit applied migrations; add a new one.
Ran migration SQL by handThe history table doesn't record it, so the runner will run it again and fail. Let the runner apply migrations.
Failing-test task: committed test + fix togetherTwo commits: git add test_file → commit, then git add code_file → commit.
git add . grabbed junkRunning pytest creates __pycache__/ and .pytest_cache/. Add files by name: git add test_validate.py.
git push pushed the wrong thingBe explicit: git push origin main.

Look-commands to type before and after

$ pwd ; ls -la                              # where am I, what's here
$ git status                               # branch + staged/unstaged/untracked
$ git branch -a                            # all branches, * = current
$ git log --oneline --graph --all --decorate   # the whole history picture
$ git log --oneline | wc -l                # how many commits on this branch
$ git show main:greet.py                   # a file's content as stored at a branch
$ docker ps -a ; docker images ; docker volume ls
$ sqlite3 shop.db ".schema"                # current database schema
