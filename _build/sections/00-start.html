How to use this pack

Read a topic, then do its labs in a real terminal until the commands come without thinking.

The idea

You already understand the concepts. What's missing is reps: typing the commands yourself, seeing the real errors, and fixing them. Every topic here has a short guide and practice labs on your laptop that grade you the way the quiz checker does. Reading alone won't fix this. Doing will.

The loop for every topic

  1. Read the topic's mental model and command tables (10–15 min). Don't memorise yet.
  2. Do the labs in order: Drill → Quiz-style → Twist. Try first, without looking.
  3. Stuck for 5 minutes? Look at the guide's tables (not the solution). Still stuck? Open SOLUTION.md.
  4. Redo it. Run ./setup.sh again and solve the lab from memory. The second clean run is what counts.
  5. Tick it in the Practice labs list. Your ticks are saved in this browser.

The Lab Practice Tool (quiz-style screen)

This is the easiest way to practise: a browser page laid out like your quiz. You get the task, a file panel to edit files, a real terminal, and a Check button that shows ✓/✗ for each check. Start it from a terminal:

$ cd Practice-Labs         # the folder you cloned (wherever it lives)
$ ./start-lab-tool.sh
# opens http://127.0.0.1:8765 in your browser. Leave this terminal open; Ctrl+C stops the tool.
  1. Pick a lab on the left. Its work/ folder is built automatically the first time.
  2. Read the task. Edit files in the panel (Ctrl+S saves) and type commands in the terminal.
  3. Press ✓ Check. Passed labs get a ✓ in the list.
  4. Press ↺ Reset lab to start that lab over, then solve it again from memory.
Save before running git

The terminal only sees what's saved to disk. After editing a file in the panel, press Ctrl+S before git add, exactly like the quiz's file panel. When a command changes a file (e.g. git merge writes conflict markers), the panel reloads it automatically.

Running a lab from your own terminal

You can also do every lab in a normal terminal or VS Code. Every lab is a folder with four files:

TASK.md

The situation and the task, worded like the quiz. Read it first.

setup.sh

Builds a fresh work/ folder with the scenario. Run it again any time to start over.

check.sh

Grades your work/ folder with ✓ / ✗ per check, like the quiz's "What was checked".

SOLUTION.md

The exact commands with a why for each, and common wrong attempts. Open it only after trying.
$ cd labs/01-shell/01-files-and-folders   # from the Practice-Labs folder
$ cat TASK.md            # or: code TASK.md  (opens in VS Code)
$ ./setup.sh             # builds work/ fresh
$ cd work                # you solve the task in here
#   ... your commands ...
$ ../check.sh            # grade yourself (works from work/ or from the lab folder)
$ cd .. && ./setup.sh    # start over and do it again from memory
Re-run setup from the lab folder, not from inside work/

setup.sh deletes and rebuilds work/. If your terminal is inside work/ when that happens, it's left in a deleted folder and commands act strangely. Always do cd .. first, then ./setup.sh, then cd work again.

Docker labs leave their container running

After a Docker lab passes, its container keeps holding its port (8080, 8081…). Before starting the next Docker lab, go back to the finished lab and run ./setup.sh to clear it, or run docker rm -f <name>. Docker must be running for Topic 4 and Topic 6.

One-time setup (do this first)

# 1. Make plain "git pull" merge when branches have diverged (the quiz assumes it does).
#    Without this, git 2.43 stops with "Need to specify how to reconcile divergent branches".
$ git config --global pull.rebase false

# 2. Optional: use nano instead of vim when git opens an editor
$ git config --global core.editor nano

# 3. Topic 6 in your own terminal only (the Lab Practice Tool does this for you).
#    Run from the Practice-Labs folder, once per terminal:
$ export PATH="$PWD/labs/bin:$PATH"
#    ...or permanently (also from the Practice-Labs folder; $PWD is saved as the full path):
$ echo "export PATH=\"$PWD/labs/bin:\$PATH\"" >> ~/.bashrc
Why hashes don't match the quiz

A commit's hash depends on its time and author, so every setup.sh run produces new hashes. Read them from git log --oneline or git reflog. Never copy them from the task text.

Terminal survival kit

Key / commandWhat it does
TabAutocompletes file names and commands. Press it constantly: it saves typing and prevents typos in paths.
↑ / ↓Brings back earlier commands so you can fix and rerun them.
Ctrl+CStops whatever is running and gives you the prompt back.
qQuits a pager. git log, git diff and man open one; you'll see a : or (END) at the bottom.
clear or Ctrl+LClears the screen.
pwdPrints where you are. Check this whenever a path "doesn't exist".
cmd --helpShows a command's options. The quiz allows this, so use it.
code fileOpens a file in VS Code. This stands in for the quiz's file panel.

Stuck inside an editor? (the merge-commit trap)

Commands like git commit (with no -m) or git merge can open a text editor inside the terminal, so you can type a message. If you don't know how to leave it, you're stuck. Learn both editors' exit keys:

vim (screen with ~ lines)

Save and quit: press Esc, type :wq, press Enter.
Quit without saving: Esc :q! Enter.

nano (shortcuts listed at the bottom)

Save: Ctrl+O then Enter.
Exit: Ctrl+X.
Avoid the editor completely

Give the message on the command line: git commit -m "message", or for a merge git commit --no-edit / git merge branch --no-edit.
